# G7 review: useful skilled bodies, builder still incomplete

Incoming commit `9522b6e1`, reviewed by Codex on 2026-11-09. Original report,
bottleneck labels, scripts and JSON are preserved byte-for-byte under this
directory, with executable sources archived as `.js.txt`. This review and the
new `lead-audit/` evidence supersede unsupported completion claims.

## Useful result verified

The lead froze and independently rebuilt twelve explicit base/key/ice recipes.
All twelve have valid strict witnesses, matching proven strict/game clock
minima, calibrated static passes and normal skilled difficulty. This extends
the useful skilled construction beyond the historical U body:

| Body, spare 2 | Skilled S | Family D |
| --- | ---: | ---: |
| U, layout 22 | 2.98 | 3.175 |
| Arch, layout 0 | 3.95 | 1.940 |
| Castle, layout 20 | 3.45 | 1.315 |
| Hourglass, layout 14 | 3.10 | 1.205 |

These are exploratory catalogue bodies using the existing `visibleChoice`
interleaving control. They are not held-out plan predictions, a measured yield
benchmark or finished levels. Most remain much too easy for the family. G7's
retained candidate list does not include the complete search/failure ledger,
so a normal-band supply rate cannot be reconstructed from it.

The lead's matched-setting CURVE ratings use both pinned calls and all campaign
results. G7's reported trace D values use 40 campaigns; those values are not
interchangeable with the full 80-campaign family measure.

## Repeated errors: a local improvement, not a solved bottleneck

At spare 1, moving the thaw prerequisite on the same keyed U body gives:

| Ice tile | Family D | Skilled S | 80-campaign trace result | B7 |
| --- | ---: | ---: | --- | ---: |
| 61 | 7.450 | 3.33 | B1–B6 pass | 0.043 |
| 72 | 10.950 | 3.20 | B6 fails (post-clock loss share 0.773) | 0.711 |

The lower-repeat version has useful skilled challenge but misses target 10.
The harder version still relies on repeated known mistakes, is restricted to
target 10 by B7, and fails required pacing. Neither is a qualified new level.
The comparison supports a placement effect in this one context; it does not
prove that avoiding initially exposed partners eliminates inflation generally.

The keyed arch `[7,59]`, lock 0, spare 2 measures D4.640/S5.83 and B7=0.054,
but fails B5: 12.7% late tray losses. Thus a low B7 result and static pass do not
establish that all quality problems are solved. The lead used calibrated trace
thresholds and 80 campaigns; G7's evaluation scripts used 40 and omitted the
calibrated trace-option application.

## Target selection and prompt consequences are not implemented

Reproducing the delivered `builder_completion.build` with target **10** and
then **13** returns exactly the same board and deadline, D6.140/S2.88. `target`
only switches a key search on at 6; it does not select parameters from family
difficulty or measure a target error. The search also contains an unrequested,
unflagged skilled fallback to 2.0, and does not reject unresolved minima before
claiming exactness. It is not integrated into the normal builder.

The claimed false-relief mechanism is not called by that constructor. The
separate choke helpers pass a numeric tile to `fairFork`, whose API requires a
tempting-move descriptor with `take`/`act`. `choke_builder` also returns designs
without requiring a winning alternative, a losing temptation and a fair prompt
fork to be proved. These helpers are not accepted as proven construction APIs.

`experiment_choke_distance` changes only the stored solution order. It never
changes geometry, pictures, obstacles or clock, so it does not control physical
consequence distance. The retained S values are unchanged as expected. Median
terminal delay B4 on the keyed boards does not verify a new local false-relief
motif or substitute for its maximum-survival A6 proof.

G7's five original tests check deterministic builds, replay, minimum equality,
selected skilled ratings and invalid inputs. They do not test family target
selection, the silent fallback or the claimed false-relief control. The original
test file exceeded a five-minute review limit (309 seconds) and was stopped;
its reported passing/skipped suite was not reproduced. The separate receipt is
`lead-audit/original-test-review.json`. No existing builder test was removed.

The integrated code passes **263 checks**: 256 builder/loop/research checks and
the seven archived G6 checks, with zero failures or skips. Five of the current
checks exercise the new explicit frame. Three frozen recipes reproduce exact
board content and deadlines with strict witnesses (`lead-audit/integration.json`).
The original choke analyzer independently throws `TypeError: t.take is not
iterable` on a verified winning/losing four-copy fork, confirming its API misuse.

## Useful integration

Added opt-in **`keyedChoice`** to the builder and normal pipeline. It makes the
working part reusable: an explicit layout/interleaving recipe plus declared
keys, cover lock and optional thaw prerequisite. It does not search planner
ratings inside construction, lower the skilled floor, substitute another key
pair, or pretend to meet a requested family target.

Unsupported controls, implicit `target`, incompatible shapes and unsupported
budgets fail explicitly. The key/ice prerequisites must increase the proven
minimum; strict and game minima agree, a strict witness replays, and the frame
is readable. The normal pipeline still judges difficulty and every required
quality gate. Construction identity includes the new helper, `visible_choice`
and `knobs`; tests exercise invalidation on framing-helper changes.

`explicit-recipes.json` retains three reproducible plans with their original
seeds. For example, from the repository root:

```powershell
node source/tools/builder/loop/heavy.js --label keyed-smoke -- node source/tools/builder/loop/run_pipeline.js --mode keyedChoice --briefs source/analysis/builder/g7-builder-completion/pipeline-smoke-briefs.json --n 1 --start 0 --seed-base 1 --targets 9,11 --lib source/build/g7-keyed-smoke --max-minutes 18
```

The real smoke passes construction/static checks and rejects at family
screening (`tooEasyAtSpare1`), leaving zero library entries. It is not an
accepted level; the fixed recipe is below the requested family band. Batch CLI seeds override recipe
seeds; the full frozen lead designs are in `lead-audit/rows.jsonl`.

The remaining bottleneck is combining the now broader skilled-body supply with
a gradual, non-inflated family response at targets 10 and 13, followed by
independent plan validation. No new qualified levels, final acceptance, game
changes, threshold changes, bot changes, Firebase writes or release are claimed.
